# وارد کردن ساده کلیدها و پایداری تانل

این صفحه به دو سؤال پاسخ میدهد:

1. چگونه کلیدها را **روی هر سرور دلخواه** (Iran یا Exit) با یک دستور ساده وارد کنم؟
2. چگونه مطمئن شوم بعد از **ریبوت** یا **بستن SSH** تانل قطع نمیشود؟

## اصل کلی

- **کلید خصوصی** (`*.key`) فقط همان سرور میماند و مجوز `600` دارد.
- **کلید عمومی** (`*.pub`) را میشود آزادانه بین سرورها و کلاینتها کپی کرد.
- Iran دو جفت کلید دارد: `omawg0` (تانل Iran↔Exit) و `omclient0` (کلاینتها). Exit فقط `omawg0` دارد.
- تمام تنظیمات بعد از وارد کردن کلید، در فایل ذخیرهشده `/etc/1mobile-runtime/<iface>.conf` مینویسند، نه فقط در حافظهٔ اینترفیس زنده.

## وارد کردن کلیدها روی هر سرور

روی سرور موردنظر:

```bash
sudo bash scripts/install.sh keys show          # کلیدهای عمومی فعلی را چاپ میکند
sudo bash scripts/install.sh keys import exit   # یا: import iran
```

اسکریپت از شما میپرسد:

| سؤال | توضیح |
|---|---|
| `omawg0 private key` | کلید خصوصی همین سرور. **Enter** = کلید قبلی بماند یا اگر نبود، کلید جدید ساخته شود. |
| `Peer public key` | `omawg0.pub` سرور مقابل. **Enter** = کلید قبلی بماند. |
| `omclient0 private key` (فقط Iran) | کلیدی که کلاینتها به عنوان `PublicKey` سرور میگیرند. **Enter** = نگه داشتن/ساختن. |

غیرهمراهی (برای اسکریپتها) هم هست:

```bash
sudo OMAWG0_KEY='...' PEER_PUB='...' \
  bash scripts/install.sh keys import exit
# روی Iran میشود OMCLIENT0_KEY='...' را هم اضافه کرد
```

پس از اتمام:

- کلیدها در `/etc/1mobile-runtime/keys/` ذخیره و اعتبارسنجی میشوند.
- فایلهای `.conf` ذخیرهشده آپدیت میشوند (Address، پورت، obfuscation، Endpoint و AllowedIPs **دستنخورده** میمانند).
- اگر اینترفیس زنده باشد، همان لحظه با `apply-iface.sh` کلیدها، آدرس و وضعیت `up` اعمال میشود؛ Peerهای اضافهشده توسط پنل حفظ میشوند (`merge_peers`). اگر نباشد، supervisor در راهاندازی بعدی آن را میسازد.
- روی Iran کلید `omclient0.pub` بهطور خودکار در `/etc/1mobile-client/server.pub` کپی میشود تا پنل هنگام ساخت کاربر از آن استفاده کند.
- در انتها `install.sh persist` اجرا و سرویسها بررسی میشوند.

> اگر کلید `omawg0` یا peer را عوض میکنید، حتماً کلید عمومی جدید را به سرور مقابل بدهید و دوباره `keys import` را آنجا اجرا کنید. روی Iran اگر `omclient0` عوض شود، کانفیگ/QR تمام کاربران باید دوباره از پنل گرفته شود.

## پایداری بعد از ریبوت و بستن SSH

تانل **هیچ وابستگی به نشست SSH ندارد**. سه سرویس systemd آن را نگه میدارند:

| سرویس | نقش |
|---|---|
| `1mobile-runtime.service` | هر ۱۵ ثانیه چک میکند اینترفیسها زندهاند؛ اگر نبودند از `.conf` و `.addr` ذخیرهشده میسازد. هر ۶۰ ثانیه هم سلامت تانل (handshake تازه + UDP probe) را بررسی میکند و بعد از ۳ تلاش ناموفق متوالی تعمیر نرم میکند. |
| `1mobile-panel.service` | پنل HTTPS (فقط Iran). |
| `1mobile-udp-echo.service` | پاسخ UDP probe برای RTT (فقط Exit). |

همه با `systemctl enable` در bootstrap نصب میشوند. برای بررسی/ترمیم یک مرحلهای:

```bash
sudo bash scripts/install.sh persist
```

دستور بالا:

- سرویسها را `enable` میکند،
- مطمئن میشود فایلهای `.conf` ذخیرهاند،
- سرویس supervisor را ریاستارت میکند (اینترفیس سالم را **پاک یا قطع نمیکند**)،
- وضعیت `is-enabled`، `is-active` و اینترفیسها را چک میکند.

بررسی دستی:

```bash
systemctl is-enabled 1mobile-runtime 1mobile-panel   #iran
systemctl is-enabled 1mobile-runtime 1mobile-udp-echo #exit
systemctl status 1mobile-runtime --no-pager
awg show omawg0
awg show omclient0      # فقط Iran
```

**تست ریبوت:** بعد از `sudo reboot` و بدون وارد کردن هیچ دستوری، از روی یک کلاینت `(مثلاً) ping 10.9.0.1` و سپس باز کردن پنل را امتحان کنید. قطع نشدن تانل یعنی مسیر ذخیرهشده درست کار میکند.

اگر سرور بهطور کامل عوض شد (دیسک جدید)، کافی است `deps` → `keygen` یا `keys import` → `fresh <role>` را اجرا کنید؛ لازم نیست کلیدها را دوباره از صفر یادداشت کنید مگر اینکه کلید قدیمی را نگه نخواسته باشید.

## چرا بستن SSH تانل را قطع نمیکند؟

اسکریپتها فقط موقع نصب اجرا میشوند. بعد از آن، فرایند تانل توسط systemd (نه توسط ترمینال شما) اداره میشود؛ بنابراین `exit` کردن SSH، بستن ترمینال یا قطع اتصال اینترنت کامپیوتر admin تأثیری بر تانل ندارد. تنها چیزی که نیاز دارد یادآوری شود، درست بودن `role` و فایلهای `.conf` است که `persist` آنها را چک میکند.
